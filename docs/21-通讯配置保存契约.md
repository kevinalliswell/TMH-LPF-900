# 通讯配置保存契约

本文描述 `tmh_core::config_store` 的存储边界。管理员权限、实验运行/保护/保存期间的操作门槛、操作者审计和应用重启由原生应用层负责。核心模块不打开通讯设备，也不把参数校验通过等同于真实设备验证通过。

## 生效状态

`ConfigStore::open(path, default)` 固定本次进程实际使用的 `applied` 配置。`snapshot()` 返回规范绝对路径、当前 UUID 版本、`applied`、最后保存的 `saved` 和 `restart_required`。

`save(expected_revision, config)` 只保存新文件，保持 `applied` 不变。`saved != applied` 时需要重启；把配置改回 `applied` 后该标志解除。重开存储才把文件内容作为新 `applied`。每次打开和成功保存均生成新的 UUID；它是当前进程内的乐观并发版本，不是配置文件内的历史记录。保存后的审计历史由应用层另行保留。

显式路径使用 `default=None`，缺少文件必须报错。默认数据目录可使用 `Some(default)`，仅在文件不存在时初始化。现有 JSON 损坏、字段非法、无法读取、悬空符号链接等情况均报错，不以默认值覆盖。已有文件的兼容默认字段仍由 `CommConfig` 的 serde 默认规则填充。

## 保存与冲突

目标路径先规范化；通过符号链接打开时，存储针对解析出的实际文件。相同目标的路径别名共用目标旁的独立 SQLite 独占锁，直到 `ConfigStore` 被释放；进程退出后由操作系统释放锁。这个锁只协调采用本协议的应用实例，不能阻止文本编辑器或其他程序修改文件。

每次保存检查调用者版本，并比较实际文件与打开/上次保存时的原始字节。检查时已存在的外部修改即使只改变空白，也拒绝覆盖。最后一次检查与替换之间仍存在一个窗口；不遵循锁协议的外部程序可能在此时写入，因此不提供对外部并发编辑的原子比较并替换保证。调用者应提示关闭应用、核对文件后重开；不能把旧草稿无条件重试到新版本。已确认快照仍描述应用最近一次读入/保存的内容，不宣称外部修改已经应用。受控重启前调用 `verify_saved_file()`，外部更改时拒绝按旧预览重启。

写入采用同目录 UUID 临时文件、独占创建、完整写入、文件同步和原子替换。首次初始化使用同目录硬链接发布，不覆盖在检查后新出现的文件。替换前失败保留原配置；替换后若目录同步失败，错误明确说明文件已经替换，内存版本和 `saved` 也更新，调用者需重读快照。临时文件只清理本次创建的路径。

Unix 在发布后同步目录；Windows 使用文件同步和系统文件替换，不声称能消除所有断电或存储硬件故障。文件系统不支持所需操作时明确报错。原子替换和硬链接的跨平台行为分别依据 [Rust rename](https://doc.rust-lang.org/std/fs/fn.rename.html)、[Rust hard_link](https://doc.rust-lang.org/std/fs/fn.hard_link.html)；独占锁依据 [SQLite 文件锁说明](https://www.sqlite.org/lockingv3.html)。

## 首版允许范围

这些范围是软件实现边界，实际仪表能力需要现场验证。

| 配置项 | 校验 |
| --- | --- |
| 串口名称 | 非空、无首尾空白/控制字符，最多 512 字节；三总线不得复用同一端口，Windows COM 名称忽略大小写 |
| 串口格式 | 波特率大于零，数据位 5–8，校验 N/E/O，停止位 1/2，超时 0.001–60 秒 |
| 采样/采集/心跳间隔 | 有限数，0.01–86400 秒；避免不可表示时长和零周期 |
| 旧采样字段 | `PERFORMANCE_CONFIG.experiment_data_interval` 是 `SAMPLING.interval_s` 的兼容别名，必须相等 |
| 缩放与气体限值 | 有限正数，流量线缆步长不能下溢为零；N₂ 缩放必须能在 i64 范围内精确编码固定保护流量 5 L/min。气体执行时仍经过不可绕过的绝对安全限值和线缆分辨率校验 |
| MFC 地址 | 1–99，四个地址互不相同；匹配当前两位十进制地址格式 |
| 温度地址与布局 | 地址 0–247；0 只为兼容仓库已有文件保留。固定 start_reg=0、reg_count=9、TEMP_CHANNELS 按 T1–T9 顺序 |

仪表负责执行温控程序。通讯配置不会把上位机改为温控闭环控制器；本模块也不自动启动仪表程序或解除保护。

# 候选安装包验收

此包用于首轮桌面模拟验收。文件名和 `manifest.json` 记录确切源码提交，`SHA256SUMS.txt` 可核对文件完整性。当前源码版本仍为 0.2.0，不能只凭版本号把候选包与 2026-08-31 的已发布包混为一谈；正式发版将另行确定版本。

## 构建与数据

候选包通过独立 `candidate` 构建特性和 Tauri 配置生成，应用名含 Candidate，使用独立应用标识。默认数据目录为系统用户数据位置下的 `tmh-lpf-900-candidate`，正式应用仍使用 `tmh-lpf-900`。候选包不接收自动更新，且只允许模拟设备；不需要发布签名密钥。

Windows 包是包含 WebView2 离线安装器的 NSIS 安装包。macOS 为包含 Apple Silicon / Intel 两种架构的 DMG。当前没有 Windows 发布者证书或 Apple 公证，签名状态不能当作已完成公开发行验收。

本机构建示例：`pnpm tauri build --ci --features candidate --config src-tauri/tauri.candidate.conf.json`。流程依据 [Tauri CLI 的配置覆盖与构建选项](https://v2.tauri.app/reference/cli/)、[Windows 离线安装器说明](https://v2.tauri.app/distribute/windows-installer/)及 [macOS 应用分发说明](https://v2.tauri.app/distribute/macos-application-bundle/)。

## 自动验证的范围

构建前执行前端类型/lint/测试/构建、IPC、Tauri 配置、依赖审计、版本一致性、Rust 格式/clippy/全工作区测试。Windows 在干净测试目录验证安装、首次窗口、正常关闭、SQLite 完整性与 schema 8、首次创建管理员前无默认账户，以及卸载。macOS 验证双架构、临时代码签名和 DMG 完整性。真实窗口中的完整人工操作、实际设备和国标实验不在这些自动检查的证明范围内。

## 人工验收步骤

1. 安装并启动，确认窗口标识为候选测试版、数据来源为模拟。首次运行创建自己的管理员；没有预设管理员口令。
2. 创建普通用户，分别登录，验证本人历史可见、他人数据不可见；锁定后重新登录。
3. 使用三项国标模板完成模拟流程，逐项确认人工步骤；验证停止、跳段记录、保护复位及程序版本。
4. 在历史查询补录单次分析所需的称量、化学成分、筛分或体积数据，以及制样/校准/外部操作记录。自定义条件须从标准模板派生并说明改动原因。
5. 在检验组报告中选择同批独立试验、填写材料与必要限值依据，检查待补测和采用/排除结果。补录实验室、报告编号、日期和复核信息，保存并导出 HTML / JSON，打印为 PDF。
6. 重新分析单次记录后检查旧组版本保持不变；添加报告资料应生成新版本，旧版仍能读取与导出。未保存资料时切页应受到保护。
7. 关闭再启动，确认历史和报告仍在。断网检查本地功能；记录实际 Windows/macOS 版本、安装/卸载表现和发现的问题。

## 回退与问题记录

先正常停止实验并完成数据保存，再关闭程序。保留候选数据目录和导出文件后可以卸载候选应用，独立正式应用不受候选默认目录影响。不要将 schema 8 数据库交给只支持旧 schema 的版本；需要回退数据时，应使用升级前独立备份，不能覆盖唯一原始记录。

反馈请保留安装包提交编号、系统版本、重现步骤、应用日志和相关导出证据。涉及真实设备的首次实验必须等型号、通讯手册、测点映射与校准资料核对及设备验收完成。

# 数据保存与恢复

本说明对应首版审查 F09。真实设备驱动尚未完成；下列验证使用模拟设备、真实 SQLite 数据库与桌面应用。

## 操作行为

采样写入失败时，实验停止并请求保护气氛。末批样本保留在内存；程序还会尝试将完整结束提交写入数据目录的 `recovery` 文件夹。样本、结束时间、运行终态与提交回执在一个数据库事务中保存，任何一步失败都会回滚。

界面显示“实验数据尚未保存”时，应保持应用打开，处理磁盘空间或目录写入权限后选择“重试保存”。保存完成前，新实验、记录删除、保护复位、软件更新与正常退出被阻止。故障未解除时重试不会丢弃原记录；成功后再确认保护状态并复位。

重启时，程序在获得单实例资格和数据目录独占锁后重放完整恢复文件。数据库已经提交、但文件尚未删除的情况使用回执去重。损坏的正式恢复文件保留并报告错误；没有完整末批记录的中断实验标为 `recovered`，且 `data_complete=false`。不得将这类记录作为完整正常实验。

如果数据库和恢复文件同时无法写入，当前进程中的末批数据仍会保留，因此正常关闭被阻止。操作系统强制结束、断电或进程崩溃仍可能使未落盘数据无法找回；软件不会承诺这种情形下的数据完整性。

默认数据目录为系统持久应用目录下的 `tmh-lpf-900`。软件测试可在启动前设置 `TMH_DATA_DIR` 到单独目录；不要将测试配置指向实验室的正式记录目录。无法确定持久目录时不静默退回临时目录。

## 验证记录（2026-09-08）

- 实际 SQLite 触发器注入末批插入、元数据更新、结束时间写入和删除失败；核对回滚、重放去重、不可改写原结束时间与原记录保留。
- 文件恢复覆盖数据库失败后的重试、提交成功但清理前中断、完整临时文件、损坏正式文件、内存/文件冲突。
- 独立测试复现普通有限小数在 JSON 默认解析后末位变化造成虚假冲突；启用 `float_roundtrip` 后相同原始记录可精确往返。无效读数及失重计算溢出保持质量提示与可恢复格式。
- 桌面双进程验证：旧代码第二次启动将未结束记录改为 `recovered`；修复后第二实例退出，原记录的结束时间保持为空。
- 原生桌面使用隔离数据库注入采样失败：5 条末批样本保留、窗口关闭被阻止、错误仍在时重试保持待保存状态；解除故障后数据库恰有 5 条样本和 1 条回执，结束时间与原提交一致，恢复文件清空，显式复位后可开始下一实验。
- 完整 Rust 测试 207 项、前端测试 29 项通过；类型检查、ESLint、Clippy、IPC 契约、Tauri 配置、前端构建、serial 特性编译及脏数据回放通过。Windows/Linux 检查以对应 PR 的 CI 为准。

仍需后续修复的独立范围：国标正常结束程序、人工操作确认、连续稳定判定、检验重复组与最终报告。硬件协议与实机实验结果仍待验证。

审查补充：末批遇到周期保存边界时仍保留给完成事务；重试先补写仅在内存的恢复记录，磁盘满留下的不完整临时文件另存检查后再写入完整记录。三项新增回归先复现失败，再验证修复。

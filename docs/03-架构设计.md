# 03 架构设计

## Cargo workspace 分层

```
tmh-next/
├─ src/                      # React 前端
│  ├─ features/              # 按页面/功能域分目录(monitor, control, experiment, history, settings, about)
│  ├─ ipc/                   # tauri-specta 生成的绑定 + channel 订阅封装
│  ├─ stores/                # zustand stores(telemetry, experiment, health, config)
│  ├─ components/            # 共享组件(StatTile, GasChannelCard, StatusDot, ...)
│  └─ styles/
├─ src-tauri/                # 薄胶水层:命令处理器、channel 泵、插件注册、capability 配置
├─ crates/
│  ├─ tmh-protocols/         # 纯帧编解码,零 I/O、零依赖(除 crc)。金帧测试在此
│  └─ tmh-core/              # 总线 actor、Transport trait、安全钳制、采样、存储、审计、实验引擎
│                            # 禁止依赖 tauri —— 必须可无头运行(CLI soak 示例)
├─ fixtures/                 # 金帧向量(golden_vectors.json)、录制的串口会话(.jsonl)
└─ docs/                     # 本规格文档包
```

**依赖方向(硬约束)**:`src-tauri → tmh-core → tmh-protocols`。反向依赖、跨层依赖禁止。
`tmh-core` 提供 `examples/soak.rs`:无头跑三总线(mock/replay)N 小时,CI 用。

## 并发模型

```
┌─ webview (React) ─────────────────────────────────────┐
│  zustand stores ← Channel 泵 / 事件监听                │
└──────────────▲────────────────────────────────────────┘
               │ tauri IPC
┌─ tokio 运行时(src-tauri + tmh-core 编排层)───────────┐
│  telemetry aggregator(0.2s tick,汇总三总线 watch)   │
│  sampler(1.0s tick → 存储写队列)                     │
│  experiment engine(1s tick,阶段推进/安全气氛)       │
│  storage writer task(rusqlite 单写者,批量事务)      │
└───▲──────────────▲──────────────▲─────────────────────┘
    │ watch/mpsc   │              │
┌───┴────┐  ┌──────┴───┐  ┌───────┴──┐
│temp bus │  │ mfc bus  │  │balance   │   ← 每总线一个 std::thread,独占串口句柄
│actor    │  │ actor    │  │bus actor │      阻塞 IO + 硬件超时(~50ms 读超时循环)
└─────────┘  └──────────┘  └──────────┘
```

- **总线 actor**:拥有 `Box<dyn Transport>`,内部循环 = 处理入站命令(mpsc)→ 轮询读 → 发布快照
  (`tokio::sync::watch<DeviceSnapshot>`)→ 健康状态机。串口阻塞读**绝不**跑在 tokio 上。
- **MFC actor 特有**:单总线 4 从站顺序轮询;内部**两级优先队列**——设定值写入(HIGH)抢占轮询读(NORMAL);
  真实带宽约 1–2Hz 全量扫(4 从站 × PV+SV = 8 次事务,9600 半双工每次 60–100ms),规格按 1Hz 设计。
- **watchdog**:某总线 actor 连续 N 个心跳周期无进展(阻塞读被坏适配器卡死)→ 强制关闭并重开端口句柄。

## IPC 设计(三层,规则:连续 ≥1Hz → Channel;低频状态跳变 → 事件;动作/查询 → invoke)

### Channel 流(前端 invoke 传入 `tauri::ipc::Channel`,丢弃即自动退订)

| 命令 | 载荷 | 频率 |
|---|---|---|
| `subscribe_telemetry` | `TelemetrySnapshot { seq, ts, temps: {T1..T9: f64?}, gas: {H2,N2,CO2,CO: {pv, sv, on}}, weight: f64?, health: {temp,mfc,balance: {connected, last_ok_ts, consecutive_errors}} }` — **一条合并快照** | 5Hz(0.2s),UI 可调 |
| `subscribe_experiment_samples` | 采样行(同 DB 行结构) | 实验运行中 1Hz |

### 事件(`app.emit`,低频)

| 事件 | 载荷 |
|---|---|
| `device-health-changed` | `{ device, connected, reason_zh }` |
| `experiment-state-changed` | `{ phase, mode, experiment_id, stage_index, total_stages, started_at, elapsed_s }` |
| `experiment-stage-info` | `{ stage_name_zh, description, target_temp, tolerance, duration_min, elapsed_min, current_temp }`(1Hz,实验中) |

### 错误约定

所有命令错误返回 `CommandError { code: string, message_zh: string, detail?: string }`。
`code` 为稳定英文标识(如 `PORT_IN_USE` / `DEVICE_OFFLINE` / `INVALID_PARAMS` / `AUTH_FAILED` /
`EXPERIMENT_RUNNING` / `CLAMP_CONFIG_INVALID`),前端按 code 分支,`message_zh` 直接可显示。

## 安全架构(硬性)

1. **钳制唯一咽喉点**:H2/CO 上限钳制实现在 **MFC actor 构帧前**的一个函数里;
   手动、实验程序、自定义程序、未来任何调用方都必经此点。配置值之上有**编译期绝对上限**
   (`H2_ABS_MAX=10.0`,`CO_ABS_MAX=10.0` L/min),配置文件被改坏也不能突破。0 值恒放行。
2. **前端不可信**:webview 只显示限值(`get_gas_safety_limits`),不参与执行;capability 清单最小化。
   Webview capability 不得授予 `updater:*` 或 `process:*`:插件在 Rust 内部注册和调用不依赖这些
   前端权限。更新、安装、重启/退出只能经带配置门控、审计和安全收尾的 Rust 命令暴露。
   `scripts/check-tauri-security.mjs` 与 CI 同时约束 capability 和 CSP，防止权限面回退。
3. **任何实验退出路径**(完成/手停/错误/引擎重启恢复)必须执行保护气氛:N2=5.0,CO=CO2=H2=0,
   且该动作写审计。实验引擎在 Rust——webview 崩溃不影响炉子安全。
4. 钳制触发 → `safety-clamp-triggered` 事件 + 审计 `GAS/clamp` 记录。

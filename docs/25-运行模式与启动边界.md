# 25 运行模式与启动边界

本批推进 #19/#79 的可验证软件边界，不能代替真实设备接入。当前仅 mock 可运行；`SerialTransport` 仅编译验证，厂家型号/协议及现场抓包未核实。real/replay 请求明确拒绝，绝不隐式降级。

## 启动顺序

1. 严格解析 `TMH_DEVICE_MODE`：未设置为 mock；只接受小写 mock、real、replay。空串、拼写错误及非文本值拒绝。
2. 确认可用模式；real/replay 在任何数据目录、数据库或设备线程创建前返回 `REAL_NOT_READY` / `REPLAY_NOT_READY`。
3. 独占数据目录，创建持久目录；失败返回可定位错误，不 panic 或进程直接退出。
4. 打开并校验配置。显式文件必须存在，损坏文件原样保留；失败不打开实验数据库、不构造总线。
5. 打开数据库、构造实际 mock hub、执行恢复。成功后才管理 AppState；失败由现有首启错误页呈现，不能进入受保护控制台。

`get_runtime_mode` 返回 `{ requested_mode, effective_mode }`。UI 仅显示 effective；查询失败显示“运行模式未确认”，不推断为模拟。不确定模式、回放和真实模式均不能调用 mock 的模拟步骤能力。首次加载、锁定和配置错误时，紧急保护不得声称未启动的设备已确认安全。

## 自动验证

- 组合根测试：real/replay 在根目录不存在时即拒绝；损坏配置原样保留且无数据库，修正后启动；显式文件缺失/数据路径为文件均失败且可返回。
- 模式测试：未知、大小写和尾部空白拒绝，不把 real/replay 映射为 mock。
- 前端：原生查询拒绝不返回 mock；只读 effective；旧字符串/损坏 DTO 拒绝；hook 错误为 unknown 且后续挂载可重试；未确认水印可见。
- 本机浏览器冒烟验证首启管理员页正常渲染。UI 单测验证错误页与水印；没有连接真实设备。

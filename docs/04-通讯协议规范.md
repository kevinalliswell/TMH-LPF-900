> 本文档 + `golden_vectors.json` 是协议实现的**完整依据**,来自旧系统实测。

## 4.1 温度控制仪表 — Modbus-RTU(RS485 半双工)

**串口**:9600 波特,8 数据位,**无**校验(N),1 停止位;读超时 1.0s(配置)。
**从站地址**:0(配置 `slave_address`)。

### 读全部温度(唯一使用的事务)

请求 = `[addr, 0x03, 0x00, 0x00, 0x00, 0x09, CRC_lo, CRC_hi]`(起始寄存器 0x0000,读 9 个)。

CRC:**CRC-16/MODBUS**(初值 0xFFFF,多项式反射 0xA001),**小端**附加。

金帧:addr=0 → `00 03 00 00 00 09 84 1d`;addr=1 → `01 03 00 00 00 09 85 cc`。

响应 = `[addr, 0x03, byte_count=18, 9×2字节大端无符号, CRC_lo, CRC_hi]`。
每寄存器 `raw × scale`(scale=0.1,配置)→ 温度°C,依序映射 T1…T9。
`signed_registers` 配置为 true 时按有符号解析(默认 false)。

### 回声跳过(**必须实现**,现场血泪)

半双工 RS485 适配器会把**发出的请求原样回显**在接收缓冲里。解析时必须在缓冲中**扫描**
CRC 有效的 0x03 响应帧,而不是从头解析:

```
for i in 0..len-4:
    if buf[i]==addr && buf[i+1]==0x03:
        bc = buf[i+2]
        if bc == 0: continue          # 回显的请求此位置是 0x00 —— 跳过
        end = i + 3 + bc + 2
        if end > len: continue
        if crc16(buf[i..end-2]) == buf[end-2..end]: return frame
return None                            # 无有效帧 = 本轮读取失败(≠ 空数据成功)
```

金帧:`回显请求 + 真实响应` 的缓冲必须提取出真实响应(见 golden_vectors.json
`extract_read_all skips echoed request`)。

**健康语义**:无有效帧 → 该轮返回**失败**(空结果),供健康检查识别断线;
禁止返回"全 None 的成功结果"(旧版曾因此把断线误判为采集成功)。

## 4.2 MFC 质量流量控制器 — Azbil CPL(RS485 半双工,共线 4 从站)

**串口**:9600 波特,8 数据位,**偶**校验(E),1 停止位;读超时 0.5s。
**从站**:H2=1,N2=2,CO2=3,CO=4(配置 `SLAVE_ADDRESS_MFC`)。
**寄存器**:PV(当前流量)= **1206**;SV(设定流量)= **1401**;读字数=2。

### 帧格式(ASCII)

```
读:  <STX> {addr:02X} "00XRS," {reg} "W," {n}          <ETX> {ck} \r\n
写:  <STX> {addr:02X} "00XWS," {reg} "W," {v1[,v2..]}  <ETX> {ck} \r\n
```
- STX=0x02,ETX=0x03;addr 为 2 位大写十六进制 ASCII(如 1→"01");
- **校验和 ck**:对**从 STX 到 ETX(含两者)**的全部字节求和,取低 8 位的**二补数**,
  格式化为 2 位大写十六进制 ASCII。
- 金帧:读 H2 PV → ASCII `\x020100XRS,1206W,2\x0393\r\n`;
  写 H2 SV=raw300 → `\x020100XWS,1401W,300\x0330\r\n`(全部 hex 见 golden_vectors.json)。

### 响应解析(**必须容忍真实帧尾**)

设备回复形如 `<STX>ADDR,VALUE<ETX><ck>\r\n`(例:`\x020100X20,30\x03F3\r\n`)。解析算法:
1. 找到 STX,丢弃其含之前;2. 截断到第一个 ETX(丢弃校验和与 CRLF);
3. 按 `,` 分割取第 2 字段;4. `float / 10` = 原始值。
金帧:`\x020100X20,30\x03F3\r\n` → 3.0;`\x02OK,1234\x03` → 123.4;空/垃圾 → None。

### 数值缩放链(与配置 `FLOW_SCALING` 联动;H2/CO2/CO=0.1,N2=1.0)

- **读**:`显示值 = parse(/10 已含) × scaling`(例:H2 原始回读 "300" → 30.0 → ×0.1 → 3.0 L/min)
- **写**:`raw = int(value / scaling × 10)`(例:H2 3.0 L/min → 300)

### 总线纪律(单线 4 从站)

- 事务严格串行:发送 → 等待 `\r\n` 结尾(或超时取部分响应);每事务前清输入/输出缓冲。
- 重试:单事务失败重试至 3 次;批量轮询对失败的气路做第二轮补读。
- **优先级队列**:设定值写入(HIGH)抢占轮询读(NORMAL)——用户点"设定"不等一轮扫完。
- 实测带宽:全量扫(4 从站 × PV+SV)约 0.5–0.8s → 轮询周期设 **1.0s**。

### 安全钳制(在此层,构帧之前)

`GAS_SAFETY_LIMITS`(默认 H2=5.0,CO=5.0 L/min):`value > limit → value = limit`;
无该气体限值则不钳;**0 恒放行**。之上再压编译期绝对上限(docs/03)。钳制发生必须返回
`clamped=true` 并发事件+审计。

## 4.3 电子天平 — RS232 ASCII 行协议

**串口**:**1200** 波特,8 数据位,无校验(N),1 停止位;读超时 1.0s。
天平**主动连续**输出行,稳定读数行含标记 **"G S"**。

### 重量解析

仅解析含 `G S` 的行;用正则 `([+-]\d+\.\d+)` 提取首个带符号小数 → 重量(g)。
非稳定行/无匹配 → None(忽略)。轮询节奏 0.1s(读行)。

### 去皮(tare)命令序列(**时序敏感,必须按此实现**)

1. 暂停采集轮询(actor 进入命令模式,与轮询互斥——旧版曾因采集线程抢读把 ACK 吃掉);
2. 清输入/输出缓冲;发送 `TARE_CMD = 54 20 0D 0A`(ASCII `"T \r\n"`);
3. 等待 1.0s;随后累积读取:最多 15 轮 × 0.15s,把到达字节拼进累积串;
   若累积串同时含 `A00` 与 `G S` 可提前结束;
4. 判定(优先级):含 **A00** → 成功;否则含稳定行且 |weight| < **0.15** g → 成功(近零);
   其余 → 失败。返回 `TareResult { success, a00_found, weight? }`;
5. 恢复采集轮询。

金帧:`"A00\r\n+0.000 G S"` → success=true, a00=true, weight=0.0;
`"+0.001 G S"` → success=true(近零);`"+5.000 G S"` → success=false。

## 4.4 设备通用行为(三总线一致,`tmh-core` 实现)

| 项 | 规格 |
|---|---|
| 轮询周期 | temp:0.2s;MFC:1.0s(全量扫);balance:0.1s(读行) |
| 失败计数 | **连续 5 次**失败 → 置 `connected=false`,关闭串口句柄 |
| 重连退避 | 断线后按 **[1, 2, 5, 10, 30]s** 序列重试(到顶保持 30s);成功即复位计数与退避 |
| 陈旧判定 | 快照 `last_ok_ts` 距今 > **5.0s**(`heartbeat_timeout`)→ UI 显示离线/数据置灰 |
| 最后有效值 | 断线期间快照保留最后有效值 + 陈旧标记,不清零(便于观察断线前状态) |
| 端口占用 | 打开失败区分 `PORT_IN_USE`(被其他程序占用,提示用户)与 `PORT_NOT_FOUND` |
| watchdog | actor 连续 N(=3)个周期无任何进展 → 强制关闭重开句柄(治坏 USB 适配器卡死阻塞读) |
| 帧日志 | TRACE 级 hex dump 收发帧(现场排障);每 100 次读输出一次错误率统计 |

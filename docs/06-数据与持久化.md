## 6.2 SQLite schema(rusqlite,WAL,单写者任务)

当前 schema 版本为 v2。升级在事务内完成：新增 `users` 表，并为 `experiments` 增加可空的 `owner_user_id` 外键与索引。v1 既有实验保持无归属，只对管理员可见；管理员可在历史详情中重新分配，且不会改写历史 `operator` 快照。

`users` 保存 UUID、规范化用户名、显示名、Argon2id PHC 哈希、角色、启用状态、首次改密标记、失败计数、锁定期限和登录/密码时间戳。密码明文不得写入数据库、审计或错误信息。

```sql
CREATE TABLE IF NOT EXISTS experiments (
    experiment_id          TEXT PRIMARY KEY,     -- uuid v4
    experiment_name        TEXT NOT NULL,
    sample_name            TEXT NOT NULL,
    sample_weight          REAL NOT NULL,        -- 初始样重 g
    start_time             TEXT NOT NULL,        -- ISO8601
    end_time               TEXT,
    description            TEXT,                 -- 备注(可空)
    operator               TEXT,
    experiment_type        TEXT,                 -- 模式ID/名称
    analysis_results_json  TEXT,                 -- GB 分析结果(JSON,含输入参数)
    created_at             TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS experiment_data (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    experiment_id       TEXT NOT NULL REFERENCES experiments(experiment_id),
    timestamp           TEXT NOT NULL,            -- ISO8601
    experiment_duration TEXT,                     -- "HH:MM:SS"
    temperature         REAL NOT NULL,            -- 样品温度 T8
    weight              REAL NOT NULL,
    weight_loss         REAL NOT NULL,            -- 失重率 % = (W0-W)/W0*100(W0>0 时)
    co_flow             REAL NOT NULL,            -- PV,L/min
    co2_flow            REAL NOT NULL,
    n2_flow             REAL NOT NULL,
    h2_flow             REAL NOT NULL,
    experiment_status   TEXT,
    system_message      TEXT
);
CREATE INDEX IF NOT EXISTS idx_experiments_name ON experiments(experiment_name);
CREATE INDEX IF NOT EXISTS idx_experiment_data_ts ON experiment_data(experiment_id, timestamp);
```

迁移策略:`PRAGMA user_version` 递增迁移脚本(新库从 v1 开始;不导入旧库)。

## 6.3 采样管线(速率与职责)

| 环节 | 周期 | 内容 |
|---|---|---|
| 遥测聚合 | 0.2s(配置 `PERFORMANCE_CONFIG.data_collection_interval`) | 汇总三总线 watch → `TelemetrySnapshot` → Channel 推前端(仅内存) |
| 实验采样 | 1.0s(配置 `SAMPLING.interval_s`) | 实验运行中:取当刻快照生成一行 `experiment_data`,推 `subscribe_experiment_samples` + 入写队列 |
| 存储写入 | ~1s 批量 | 单写者任务:事务内批量 INSERT;实验结束/停止时强制 flush |
| 陈旧判定 | 5.0s(`heartbeat_timeout`) | 快照过期 → UI 置灰 |

上表三个周期由后端从 `comm_config.json` 装载后生效,并通过 `get_runtime_settings` 回报前端,
前端不得再各写一份常量。总线轮询周期(temp 0.2s / MFC 全量扫 1.0s / balance 0.1s)属协议层参数,
见 docs/04 §4.4,不在此配置。

实验计时以**单调时钟**推进:引擎按两次 tick 之间真实经过的时间前进,唤醒按固定 deadline 对齐,
使保温时长不随每轮采样/入库耗时正向漂移。

天平断线时 weight 取 0.0 记录并在 `system_message` 标注"天平离线",**不得丢行**(旧版曾因 None 静默丢采样点)。
该占位行只用于保持序列连续,**不得进入 GB 计算**:还原度取还原段内最后一条有效称量,
还原速率指数只对还原段内的有效采样做最小二乘(docs/05 §5.6)。

采样缓冲有上限(约 2000 行);SQLite 持续写失败时丢弃最旧行并计数,首次失败与其后每 12 次失败
写一条 `sample_flush_failed` 审计,恢复后写 `sample_flush_recovered`——绝不静默丢整场数据。

## 6.4 comm_config.json(**沿用旧 schema**,serde 默认值兜底)

```jsonc
{
  "COM_RS485_MFC":    { "port": "COM12", "baudrate": 9600, "bytesize": 8, "parity": "E", "stopbits": 1, "timeout": 0.5 },
  "COM_RS485_TEMP":   { "port": "COM10", "baudrate": 9600, "bytesize": 8, "parity": "N", "stopbits": 1, "timeout": 1.0,
                        "slave_address": 0, "start_reg": 0, "reg_count": 9,
                        "TEMP_CHANNELS": ["T1","T2","T3","T4","T5","T6","T7","T8","T9"],
                        "scale": 0.1, "signed_registers": false },
  "COM_RS232_Balance":{ "port": "COM15", "baudrate": 1200, "bytesize": 8, "parity": "N", "stopbits": 1, "timeout": 1.0 },
  "SAMPLING":         { "interval_s": 1.0 },
  "PERFORMANCE_CONFIG": { "data_collection_interval": 0.2, "experiment_data_interval": 1.0, "heartbeat_timeout": 5.0 },
  "SLAVE_ADDRESS_MFC": { "H2": 1, "N2": 2, "CO2": 3, "CO": 4 },
  "FLOW_SCALING":      { "H2": 0.1, "N2": 1.0, "CO2": 0.1, "CO": 0.1 },
  "GAS_SAFETY_LIMITS": { "H2": 5.0, "CO": 5.0 }
}
```

缺省兜底:FLOW_SCALING 缺失 → 0.1;GAS_SAFETY_LIMITS 缺失 → {H2:5.0, CO:5.0}。
加载时 `validate()`:端口非空、限值为正、scale≠0、从站地址不冲突;校验失败 → 启动进入
"配置错误"页并拒绝开总线(**绝不**静默用默认值覆盖用户文件——旧版曾因此丢过现场配置)。
写回采用"读-改-写 + 原子替换(临时文件+rename)"。

## 6.5 审计日志(独立于诊断日志)

每行一条 JSON:
```json
{"ts":"2026-07-02 15:04:05","category":"GAS","action":"set_flow","result":"SUCCESS","operator":"张三","detail":{"gas":"H2","value":3.0}}
```
- category ∈ `APP, EXPERIMENT, GAS, BALANCE, EXPORT, AUTH, CONFIG`;
  result ∈ `SUCCESS, FAILURE, REJECTED`;operator 缺省 `"system"`;detail 过滤 null。
- 必审计点:
  - `APP`:start / exit / start_blocked / install_update;
  - `AUTH`:bootstrap_admin / login / logout / lock_session / change_password /
    create_user / update_user / reset_password;
  - `EXPERIMENT`:start / stop / completed / error / stage_enter / skip_stage_requested /
    skip_stage / safety_atmosphere / crash_recovery / delete / analyze /
    set_experiment_owner / sample_flush_failed / sample_flush_recovered;
  - `GAS`:set_flow(含 clamp)/ on_off / open_all / close_all / shutoff / emergency_safe_shutdown;
  - `BALANCE`:tare;
  - `EXPORT`:export_data / generate_report;
  - `CONFIG`:update_comm_config(随通讯设置写回落地,见 docs/10 M4)。
- **operator 必须是执行该动作的登录用户显示名**,而不是 `"system"`;未登录即可调用的
  紧急停机记为 `"anonymous"`,仅进程自身的动作(启动/退出/崩溃恢复)才记 `"system"`。
  口令、口令哈希、临时密码一律不得出现在 detail 中。
- 写入:append-only,行缓冲即时 flush;GAS/EXPERIMENT 类别额外 `sync_data()`(掉电保护);
  日滚动 `audit.log.YYYY-MM-DD`,保留 180 天;**写失败静默计数,绝不抛给业务**。

## 6.6 账户与授权

> 本节取代旧版"管理员口令"设计。旧方案(PBKDF2-HMAC-SHA256 / `config/auth.json` /
> 默认口令 `1952`)**已废弃**,不得再实现:系统没有默认口令,首次启动由操作者创建首位管理员。

- 口令存 SQLite `users.password_hash`,**Argon2id** PHC 字符串 + 随机盐(见 6.2)。
- 密码 10–128 字符;连续 5 次失败锁定 15 分钟;**锁定期满后失败计数清零**,重新开始新的计数窗口。
- 用户名不存在时仍执行一次等价的哈希校验,使登录耗时不泄露账户是否存在。
- 会话仅存在于 Rust 内存,空闲锁定默认 15 分钟(`TMH_IDLE_TIMEOUT_S` 可覆盖,钳制在 1 min–8 h)。
- 保护动作由**角色**而非口令把关:
  - 删除实验记录、用户管理、调整实验归属、安装更新 → 仅 `ADMIN`;
  - 修改通讯配置/安全限值 → 仅 `ADMIN`(随 M4 通讯设置写回落地);
  - 实验运行期间的控制动作 → 该实验的 owner 或 `ADMIN`。
- 所有认证与用户管理动作写 `AUTH` 审计(见 6.5),失败记 `REJECTED`。

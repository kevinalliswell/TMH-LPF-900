# 09 发布与部署

## 9.1 打包(Windows 为生产目标)

- **NSIS** 安装包,perMachine;`bundle.windows.webviewInstallMode = { "type": "offlineInstaller" }`
  ——内嵌完整 WebView2 离线安装器(约 +127MB)。**禁止** downloadBootstrapper/embedBootstrapper
  (目标工控机可能离线,联网引导必失败)。
- 备选 CI profile:`fixedRuntime`(约 +180MB,完全确定版本,适配 IT 冻结镜像的站点;
  代价是 WebView2 安全补丁责任自负)。
- macOS `.app` 仅开发自用,不做公证分发。
- 低端工控核显兼容:预留通过环境变量/`additionalBrowserArguments` 关闭 GPU 加速的开关,
  遇渲染异常时现场可用。

## 9.2 签名(两把独立的钥匙,缺一不可)

1. **Authenticode**(exe/安装包)——过 SmartScreen/Defender。2023 后 CA 规则要求私钥进硬件:
   实操选 Azure Trusted Signing(成本最低)或 OV/EV 证书 + 云 HSM,CI 中 signtool 步骤完成。
2. **Tauri updater minisign 密钥**(`tauri signer generate`)——公钥烧进 `tauri.conf.json`,
   更新器强制校验且**无法关闭**。⚠️ **私钥丢失 = 所有已装机器永久脱离更新通道**:
   CI secret + 离线备份双保存,记录保管人。

## 9.3 自动更新(承接旧 issue #35 的结论)

- 更新检查默认**关闭**,`config` 开启;检查结果进 About 页 + `update-status` 事件 + 审计。
- 检查对已登录用户开放，安装限管理员；检查拒绝/离线失败和安装拒绝/失败/成功均有唯一终局审计。安装需空闲、无待保存数据且无去皮任务，成功审计先于应用重启。检查功能关闭时保留`enabled=false`的状态响应。
- 清单契约:静态 `latest.json`(version + platforms.windows-x86_64.{url, signature}),
  **必须匿名可达**。源码仓库已于 2026-10-27 设为公开；应用端点改为本仓库的
  `releases/latest/download/latest.json`。
- 匿名请求已验证可取得本仓库已发布 `v0.2.0` 清单；当前源码/应用版本也是 `0.2.0`，
  这只证明清单可达，不代表存在更新或桌面端升级演练已通过。release workflow 生成的草稿
  必须经维护者发布后才公开。
- 旧配置指向的 `TMH-LPF-900-releases` 仓库不存在，已从端点移除。若 USTB 网络实测无法
  稳定访问 GitHub，再选择独立公开托管、Gitee Releases 或阿里云 OSS；不要把不可达性当作已解决。
- 已发布的 `v0.2.0` 安装包仍包含旧 endpoint，且发布资产/tag不得覆盖。用户需先通过公开 Release 页面或 U 盘手动安装包含新 endpoint 的后续版本，之后才可测试应用内升级。
- 无论更新器状态如何,**签名 NSIS 安装包 + U 盘**是第一分发路径(离线机器的现实)。

## 9.4 版本与发布流程

- 版本严格使用 SemVer `MAJOR.MINOR.PATCH`；**单一来源**为 `package.json`，同步脚本更新
  Cargo workspace、`tauri.conf.json` 与 About 显示，防止包、二进制和更新器版本漂移。
- 流程:CHANGELOG(Keep a Changelog)`[Unreleased]` 积累 → 发版 PR(bump + 归档)→
  合并 main → tag `v<version>` → CI 构建、签名、出 NSIS + `latest.json`,发布到 Releases/OSS。
- Release 只能由 tag 触发；CI 校验 tag、所有版本点、CHANGELOG，并要求 tag 指向 `main` 顶端。
  具体版本门禁与路线见 `docs/12-版本治理路线.md`。

## 9.5 现场部署规程(写入交付文档)

- **安装新版前必须卸载/禁用旧 PySide6 版**——单实例插件只防新程序自身,防不了旧程序抢 COM 口;
- 首启：创建管理员（无预设账户或默认口令）→ 按已核准的设备参数录入串口/从站/限值 → mock 模式培训。
  真实设备枚举、连接试读和参数核验须等型号协议及硬件验收完成后执行。
- 试运行期:新旧程序**分时**验证同一实验,数据比对通过后旧版退役。

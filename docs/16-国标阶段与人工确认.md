# 国标阶段与人工确认

依据用户提供的三份正式 PDF，页码与条款对应见 [国标需求依据](13-国标核对与首版需求.md)。本次修复采用 `GB-PROCEDURE-2026-09-08.1` 程序版本；Rust 执行与浏览器预览共用 `config/standard_programs.json`。原有历史记录仍保留当时的程序快照，不自动改写。

## 责任边界

温度程序由仪表执行。上位机读取温度、判断阶段条件、控制气氛并记录数据；关炉、取管等外部操作由操作员完成并确认。当前运行仍仅支持模拟设备，代码中的 `set_temp_target_c` 只驱动模拟温度，不能作为真实温控参数写入实现。

料层上、中、下测点对应、标态流量、气体纯度、仪器校准、实际外部操作和制样须通过设备联调与人工记录核实。软件流程测试不能得出“全过程符合国标”的结论。

## 阶段规则

- 启动和每次阶段切换均等待气氛写入回执。回执前不能累计该阶段暴露时间，也不能跳段或确认人工步骤；通信等待计入实验总时长。
- 恒温阶段仅累计温度在容差内的连续时间；越界或无效温度使连续计时归零。原生程序在关键测量失效时停止并请求保护。
- 保存和启动均校验类型/时长组合：恒温、还原、吹扫必须为正时长，升温、冷却、人工确认必须为 0。旧自定义程序不匹配时仍可查看，但不能按新语义启动，须明确修改后保存。
- 还原和吹扫按气氛确认后的固定时长结束。温度偏离写入记录，不通过自动延长还原改变实验制度。
- 冷却采用严格小于限值判定。浏览器和原生模拟温度向环境温度下降，不能把冷却限值当作恒温目标。
- 吹扫、人工确认、冷却不能通过“跳过阶段”绕过。前段升温、恒温、还原可带原因跳段，记录明确标识偏离。

## 人工记录与过期请求

界面在打开确认窗口时固定实验编号和阶段编号。后端只接受本次实验所有者或管理员的操作，并分别在排队、实际执行时检查阶段和回执状态。重复请求和旧弹窗不能确认下一步。

控制周期先记入实际经过时间；如果定时条件恰好推进阶段，旧阶段的排队请求拒绝执行。动作实际执行前将操作者 ID、显示名、请求时间、执行时间、实验经过时间和备注存入运行记录。存储失败时不释放人工步骤，原生实验停止并进入保护/保存流程。

每条新原生样本保留阶段编号及连续恒温时间。报告显示程序版本、设备模式、结束结果、人工确认和跳段记录；所有人工文本经 HTML 转义。人工确认是操作员声明，不是仪器自动验证外部动作。

## 正常结束与异常保护

正常结束保留已确认的末阶段气氛：13241 为四路停气，13242/13240 为 N₂ 5 L/min。后端检查四路测量新鲜度、已确认设定值及非氮气实测流量接近零；保护锁存或结束状态不明确时不认定正常结束。

停止、设备故障、保存故障及应用退出仍请求固定保护气氛（H₂/CO₂/CO 0，N₂ 5 L/min）。正常结束后若终态保存失败，额外保护请求的结果单独审计；原始完成批次保持不可变，以便幂等重试。正常结束的气氛确认与后续保存故障的保护结果不能混作同一次动作。

## 验证

- 独立核心用例：连续恒温、温度缺失、固定还原/吹扫、严格冷却、人工步骤不可自动完成、不可跳过保护尾段、初始与切换回执、重复与过期确认、三种正常结束气氛。
- 原生模块：实际动作时间连续、定时推进与跳段竞争、错误操作记录不推进阶段、确认操作者留痕、结束时 SV/PV 与新鲜度校验。
- 浏览器自动测试：13241 完整流程在取管处等待确认，结束保持停氮；13240 两次人工确认及严格冷却，旧确认拒绝推进；弹窗保持用户实际查看的阶段。
- 实际浏览器构建验证：13241 在人工取管处持续等待，界面不显示跳段，备注可输入；确认后回到空闲且四路 SV 均为零；浏览器控制台无警告或错误。

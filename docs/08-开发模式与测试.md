# 08 开发模式与测试策略

## 8.1 运行模式(`TMH_DEVICE_MODE=real|mock|replay`,或 config 覆盖)

在组合根解析一次,选择每总线的 `Transport` 实现;`get_runtime_mode` 暴露给前端,
非 real 模式状态栏常驻水印。

### MockTransport(合成物理)

在**字节层**应答:收到合法请求帧 → 用 `tmh-protocols` 构造合法响应帧。内置简单物理模型:
- 温度:向"当前 MFC 设定推断的目标"缓慢趋近(升温 ~10°C/min 快进可配),9 路加小噪声;
- 流量:PV 在 SV 附近一阶惯性趋近 + 噪声;SV 回读 = 最近写入值;
- 重量:实验还原阶段按指数衰减失重曲线,平时小漂移;去皮后归零 + `A00` 回复;
- 故障注入(dev 面板/env):丢帧率、坏校验率、回声、断线 N 秒——用于开发重连/容错 UI。

### ReplayTransport(回放真实会话)

- `SerialTransport` 支持**录制模式**:把每次收发记为一行 JSONL
  `{"t": 秒偏移, "dir": "tx"|"rx", "bytes": "hex"}`,含真实时序间隙;
- Replay 按时间轴回放 rx(可倍速),校对 tx 是否与录制一致(不一致告警);
- 现场排障工作流:实验室录制异常会话 → 拷回开发机回放复现。
- `fixtures/` 至少维护一份**脏会话**(含回声帧、半帧、坏校验、断线段)用于 CI。

### 前端独立开发

`pnpm dev:web` 纯 Vite 模式下,`src/ipc/` 提供 mock 绑定(TS 内合成 TelemetrySnapshot 流),
UI 开发不需要起 Tauri。真实/浏览器双模式由一个 `isTauri()` 分派。

## 8.3 CI(GitHub Actions)

- 矩阵:windows-latest(**主**,生产目标)+ ubuntu-latest(快速反馈)。
- 步骤:`cargo fmt --check` → `cargo clippy --workspace -D warnings` → `cargo test --workspace`
  → `pnpm typecheck && pnpm lint && pnpm test` → `pnpm tauri build`(仅 windows,产物留存)
  → soak 短跑(replay 脏会话 5 分钟)。
- 合并条件:全绿。主干保护,squash 合并。

### 依赖漏洞门禁

- npm 生产依赖在每次 CI 执行 `pnpm audit --prod --audit-level moderate`；中高等级命中直接失败。
- RustSec 接入评估：仓库已提交 `Cargo.lock`，适合用 `cargo-audit` 扫描 RustSec Advisory DB；但 CI
  不得每次无版本约束地 `cargo install` 最新版。治理批次先启用 Cargo Dependabot 持续告警，随后用独立 PR
  固定 `cargo-audit` 版本/安装方式并清零初始基线，再将 `cargo audit --deny warnings` 加入 PR 与 Release
  required check。过渡期每次正式发版必须附人工 `cargo audit` 结果；任何豁免须记录 advisory、可达性分析、
  负责人和不超过 30 天的复查日期。该门禁由维护者负责，跟踪于 #23。
